## Hướng dẫn thực thi

1. **Môi trường**
   - Chạy `pnpm dev` với DB dev (`pickory`), đã chạy `pnpm db:seed`.
   - Nếu port 3000 bị Windows giữ, chạy API ở port khác và proxy tạm. Không sửa cấu hình đã commit.
2. **Dữ liệu test**
   - Mọi email dùng dạng `mt-<runId>-<tên>@pickory.test`, mọi mã role dùng tiền tố `mt-`.
   - Tạo admin test bằng `pnpm admin:create -- --email mt-<runId>-admin@pickory.test --password <mật khẩu mạnh>`.
   - Không khóa, sửa hay xóa dữ liệu có sẵn không thuộc lần chạy này.
3. **Email**: đọc link xác thực, đặt lại mật khẩu, lời mời từ thư mục `.dev-outbox` của API (`metadata.token` hoặc link trong `text`).
4. **Thao tác DB**
   - Chỉ được sửa DB để giả lập thời gian, cụ thể là lùi `expiresAt` của `sessions` hoặc `email_tokens`.
   - Được truy vấn DB để kiểm tra sự thật (ví dụ email gốc còn không, số dòng audit).
   - Ghi rõ câu lệnh vào cột Ghi chú.
5. **Kiểm tra API**: dùng `page.request` hoặc `APIRequestContext` của Playwright, giữ cookie của context tương ứng. Mỗi vai trò dùng một browser context riêng.
6. **Bằng chứng**: ảnh chụp lưu ở `.playwright-mcp/identity-mt/<ID>.png` (thư mục đã gitignore). Case FAILED bắt buộc có ảnh.
7. **Không sửa code**: thấy lỗi thì chỉ ghi FAILED.
8. **Dọn dữ liệu**: sau khi chạy xong, xóa dữ liệu có tiền tố của lần chạy này, ghi lại cách dọn ở cuối file.

**Tài khoản dùng chung** (tạo ở bước chuẩn bị, admin tạo qua UI nếu được):

- `ADMIN`: admin test.
- `SALES`: nhân viên role `sales`.
- `SUPPORT`: nhân viên role `support`.
- `HR`: nhân viên role `mt-hr` gồm `staff:read`, `staff:manage`, `roles:manage`.
- `CUST`: khách đăng ký bằng email, mật khẩu.
